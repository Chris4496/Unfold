# 開始前的兩次確認與限制處理

這是主 agent 的執行契約，不派給使用者角色。兩關都通過才派角色；「完成整輪」不代替對具體方案的知情確認。兩關可以一次呈交；已明確選擇的內容不必重問，保留原始訊息即可。

## 關卡一：讓用戶知道會模擬哪些人

報告主文先寫「將啟動 N 個使用者 agent」，N 等於 Persona 名單長度，不含分析／審核角色。展示每人的身份背景、生活／工作處境、使用動機、科技習慣、隱私態度、起始情境、開放目標、預計範圍及跨角色關係。解釋差異如何幫助觀察，避免五個名字其實同一種人。

向用戶提出確認、增減或修改方案的選擇。取得覆蓋人數、名單與卡片的回覆，保留原文、可核查來源、版本和實際時間。提案仍是 pending；人類決定另存。不能報告 pending 卻派發角色，也不能標「待事後確認」後繼續。

## 關卡二：先核對本輪能怎樣使用，再讓用戶決定

核對本輪所需條件，不跑全面功能驗收：

- 產品入口／版本、已授權的本機啟動方式；
- 合成帳戶、身份權限、資料起點與角色隔離；
- UI 工具能否操作所需入口，是否支持本輪的輸入方式；
- 產品 AI、整理或搜尋是否走真實服務、規則替代或示範結果，不讀取金鑰內容。**若委託人要求把產品 AI 改接到另一個模型後端，先核對產品預期的請求／回應形態（串流或非串流、是否 OpenAI 相容、認證方式與來源限制）與替代後端的契約是否一致。只有「改環境變數、零程式碼修改」才算本階段可做的準備；需要改動產品程式，或另加一層轉接服務時，屬工程範圍，須另呈最小計劃並單獨取得批准。**
- 執行模型能否建立獨立會話、指定模型、延續圓桌記憶；
- 合成素材、跨角色時序、等待條件與完成後整理 Dashboard 的能力。

資料不足標未知並列處理選項，不假設服務已正常。必要的環境準備在原有授權內執行；不以 readiness 為由直接寫資料庫、繞過產品授權、修復產品或安裝全域工具。

每項限制或指定替代操作，用日常語言呈交：

| 需決定的事 | 影響的角色／流程 | 可選方法 | 方法對本輪結論的影響 | 你的選擇 |
| --- | --- | --- | --- | --- |
| 麥克風不納入觀察 | 日記輸入 | 打字代替原本說出的話／略過輸入／另安排語音環境 | 文字替代仍可觀察儲存後體驗，不能評價錄音與轉寫 | 待確認 |
| 產品 AI 未啟用 | 整理、搜尋、提示 | 接受規則版本／略過相關結論／先安排服務／暫停 | 規則版本結果不能外推為真實 AI 表現 | 待確認 |

只提出適用選項，可推薦但不能自選。「無視」表示接受該環境繼續、保留影響說明，不表示問題不存在。每項選擇及完整執行方案都要得到明確確認；沒有發現限制，也要呈交核對結果後確認開始。

新限制改變角色、可用路徑或結論範圍時，暫停受影響操作，更新版本與確認；無影響的已確認部分可繼續。選擇「先處理」或「暫停」不構成開始許可；處理完成後更新核對結果再確認。

## 把「打字模擬說話」保留為輸入替代

使用者說「不需要測 mic」時，不自行導入「無麥克風」情境。若尚未說明替代方法，確認是否用文字代替話語；若已指定，直接記錄該原文與範圍，不反覆問同一選擇。

對角色只說最低必要的操作約定，例如：「本輪不操作錄音硬體。當你想說話時，在文字入口輸入你自然會說出的話，再正常繼續。這是本輪操作約定，不是產品故障。」角色可以有語音偏好，但不能對安排的替代操作編造失望。

在事件中標 `observation_class: agreed_substitution`，關聯決定 ID；文字、儲存及後續狀態是實際 UI 觀察，錄音、音質、轉寫準確度與完整語音旅程是未觀察。不能聲稱已實際說話、錄音成功或取得真實逐字稿。若必須經故障頁才能輸入，先呈交此影響，不能默認把故障納入體驗。

四種邊界保持分開：`product_experience` 實際產品體驗、`environment_limitation` 執行環境／工具受阻、`excluded_scope` 人類排除的環節、`agreed_substitution` 事先同意的替代操作。不能把後三類自動算成產品摩擦。意外遭遇故障須保留原始紀錄，受污染的感受不靠改標籤變成正常體驗。

## 可選的結構檢查

Agent 1 報告使用 `agent1-analysis.md` 的 schema 2。另存 `readiness-plan.json` 和 `human-decisions.json`。以下是格式示例，不是批准憑證：

```json
{
  "schema_version": 1,
  "plan_version": "p1",
  "report_version": "v1",
  "checks": [{"area": "語音輸入", "status": "limited", "detail": "本輪不操作 mic，使用文字替代", "constraint_ids": ["input-1"]}],
  "constraints": [{
    "id": "input-1", "type": "substitution",
    "summary": "打字輸入角色原本會說出的話",
    "affected_roles": ["role-1"],
    "options": [{"id": "type-speech", "label": "文字代替話語", "method": "使用現有文字入口", "evidence_boundary": "只觀察內容輸入與後續體驗，排除錄音和轉寫", "can_start": true}]
  }]
}
```

`checks.status` 為 `ready/limited/blocked`；limited/blocked 必須引用 constraints。`constraints.type` 為 `environment/agent/excluded_scope/substitution`。所有選項須有方法與結論邊界；「先處理／暫停」的 `can_start` 為 false。無限制時 constraints 可為空，但 checks 不能為空，確認仍必須存在。

```json
{
  "report_version": "v1", "plan_version": "p1",
  "persona_confirmation": {
    "status": "confirmed", "message": "此處保存用戶確認人數及卡片的原文",
    "source_ref": "可核查的原始人類訊息位置", "timestamp": "實際取得的帶時區 ISO 時間"
  },
  "execution_confirmation": {
    "status": "confirmed", "message": "此處保存用戶確認限制選擇及執行範圍的原文",
    "source_ref": "可核查的原始人類訊息位置", "timestamp": "實際取得的帶時區 ISO 時間"
  },
  "constraint_choices": [{"constraint_id": "input-1", "option_id": "type-speech"}]
}
```

`python3 scripts/agent1.py validate-start report.json readiness-plan.json human-decisions.json` 只檢查人數、版本、結構、兩關紀錄與逐項選擇是否完整，未確認或不可開始選項會拒絕。**不能證明訊息真是人類提供，也不能理解批准原文是否真的涵蓋所列選擇；主 agent 仍須核查原始訊息。** 格式通過不會啟動任何角色。舊 run 的 schema 不回填、不改寫。
