## 1. 評估邊界

**產品版本**
- `unfold/app.json`：Expo 專案 `Unfold` v1.0.0（Expo SDK ~57，React Native 0.86.3，expo-router ~57）；iOS / Android / Web 三平台。
- Git 提交狀態：未查閱（無列舉工具），以工作目錄當前內容為準。

**資料來源**
- 需求主張：`README.md`、`docs/Project_Proposal.md`、`docs/Interim_Progress_Report.md`、`docs/Interim_Progress_Report_zh.md`（後者為最新修訂版，明確承認原型現狀與文件差距）。
- 實作證據（逐一開啟閱讀）：`unfold/app/` 全部路由 14 個畫面（`_layout`、`index`、`onboarding`、`write`、`saved`、`diary`、`day/[date]`、`ask`、`prompt`、`prepare`、`review`、`shared`、`case`、`settings`、`privacy`、`worker/index`、`worker/[id]`）、`unfold/src/`（`store.tsx`、`types.ts`、`useVoiceCapture.ts`、`transcribeAudio.ts`、`recordingDraft.ts`、`lib/organise.ts`、`lib/deidentify.ts`、`lib/ask.ts`、`lib/dates.ts` 引用、`lib/text.ts` 引用、`lib/samples.ts`、`lib/transcriptText.ts`）、`package.json`、`app.json`、2 個測試檔（`deidentify.test.ts`、`organise.test.ts`，共 6 個測試）。

**可操作環境**
- 本輪僅靜態分析。執行期模擬需要：Expo dev server（`npm run web` 或真機）、一支 **受限、低額度、僅語音轉寫** 的 ElevenLabs 測試金鑰（委託人提供並放入 `.env.local`，本團隊不讀取該檔，只確認其存在與否由操作者回報）、合成音頻與合成文字輸入。

**不可測範圍（本輪及下階段的先天限制）**
- 無真實後端：社工端是同機模擬，跨裝置、跨帳戶交接不存在，無法測試。
- 無帳戶／身份系統：社工身份驗證、權限控管未實作，無法測試。
- GenAI 分類、跨記錄語意聯結、GenAI 自然語言問答：未實作（現為關鍵字規則），無法測試其品質。
- 轉寫準確率（尤其粵語）：需合成音頻＋API 呼叫；在「不得連網」限制下本輪無法測試，下階段需委託人另行授權。
- 提示閾值的臨床適切性：佔位規則，非臨床判斷，不可給任何臨床結論。

**敏感風險**
1. **API 金鑰內嵌**（README 自述已知問題）：`EXPO_PUBLIC_ELEVENLABS_API_KEY` 被打包進客戶端（`src/transcribeAudio.ts`），任何取得 build 者可提取並消耗額度。正式發佈前為阻塞項；測試必須用受限金鑰。
2. **未成年人**：目標用戶含中學生；實作無年齡區分、無監護人同意、無保護流程。未成年人及敏感資料不作實際代理測試輸入，一律合成。
3. **心理支援主題**：提示文案涉及「困難持續」表述；本評估不產生診斷、分流或臨床結論。
4. **語音上雲**：原始設計偏好設備端轉寫，實作改為 ElevenLabs 雲端（onboarding 第 2 步及隱私頁有告知並要求勾選同意）。屬已揭露的架構折衷，需在測試中驗證告知文案與實際資料流一致。
5. **去標識化缺口**：`deidentify.ts` 為英文格式正則（英文街名、英文校名、Mr/Ms、HK 電話、電郵），**中文姓名、中文地址、粵語口語識別資訊不覆蓋**（中期報告中文版自認已知缺口）。合成測試含中文識別資訊時預期會洩漏，應如實記錄為產品缺口而非測試失誤。
6. **本地資料未加密**：全部狀態以 JSON 存於 AsyncStorage（key `unfold.v1`），含完整文字稿與（原生平台）音頻路徑。

## 2. 流程圖及狀態

三態標記：**【文件】**＝僅文件主張；**【實作】**＝程式碼可觀察（未執行驗證）；**【未知】**＝無法確認。

### 學生端

**J1 首次啟動與資料處理同意**
起點：首次開啟 →【實作】`index.tsx` 檢查 `store.onboarded`，未完成導向 `/onboarding` →【實作】三步說明（自由記錄／轉寫與本機儲存／分享需批准）→ 判斷：第 3 步勾選「我理解錄音由 ElevenLabs 轉寫…」【實作】未勾選時 Start 按鈕 disabled → 終點：`completeOnboarding()`，回主頁。
例外：無「拒絕並退出」分支【未知：是否應有，文件未明】。
對照：文件主張「首次使用了解資料儲存、雲端整理與背景分析後確認設定」【文件】；實作勾選只涵蓋轉寫與分享兩層，**無獨立的「雲端整理授權」設定**（因無雲端整理）【實作缺口】。

**J2 自由記錄 → 轉寫 → 儲存**
起點：主頁大按鈕【實作】→ 行動：`useVoiceCapture.start()` 請求麥克風權限並錄音【實作】→ 再按停止 →【實作】`stageRecording` 暫存 → 導向 `/write` →【實作】`transcribeRecording()` 將音頻 POST 至 ElevenLabs Scribe v2 →【實作】`readTranscript()` 經 opencc 簡轉繁（hk）→ 文字填入編輯框，可修改 → 判斷：文字非空才可按「Save on this phone」【實作】→【實作】`addEntry()`：`annotateEntry` 做去標識、主題與屬性關鍵字標註，存 AsyncStorage → 終點：`/saved` 顯示「Received. This entry has been saved.」＋可選事發時間（Today/Yesterday/A few days ago）【實作】。
例外／取消：① 麥克風拒絕或失敗 → 直接進 `/write?reason=mic` 純打字【實作】；② 「Type instead」跳過錄音【實作】；③ 空轉寫 → 顯示「No words were heard…」【實作】；④ 轉寫失敗 → 顯示失敗文案並可打字【實作】；⑤ 轉寫中離開 → 行為【未知】（未見取消以外的保護）；⑥ 錄音後不儲存直接返回 → draft 保留於記憶體，行為【未知】。
對照：文件主張「AI 可簡短確認、鼓勵或邀請補充」——實作為**固定靜態文案**（saved 頁確認語＋可選時間標註），非 GenAI 生成【文件主張未實作】；「不反覆追問、可直接結束」【實作，與文件一致】。

**J3 月曆回顧與刪除**
起點：主頁月曆圖示或「N notes on this phone」→【實作】`/diary` 月曆網格，有記錄日底色標記，附「These summaries describe what you said. They are not an assessment.」→ 行動：點日期 →【實作】`/day/[date]` 顯示 `dailySummary`（主題關鍵字組成的中性句）＋各條全文＋可選事件時間 → 判斷：刪除需兩步確認【實作】→ 終點：單條刪除或返回。
例外：無記錄月份顯示「No notes this month.」【實作】。
對照：「月曆不顯示心理標籤／分數」【實作，與文件一致】；每日摘要由關鍵字主題生成，非 GenAI 摘要【實作落差，品質未驗證】。

**J4 Ask your diary 查詢**
起點：主頁放大鏡圖示 →【實作】`/ask` 輸入問題（含兩個建議句式）→【實作】`askEntries()` 本地停用詞過濾＋關鍵字計分，取前 3 條 → 判斷：有匹配 → 引用原話＋日期＋可跳回 `/day/[date]`；無匹配 →「I could not find that in the notes on this phone.」【實作】→ 終點。
對照：文件主張 GenAI 自然語言理解、按日期排列多條來源——實作為關鍵字檢索，**非 GenAI**【文件主張未實作】；「答案只來自本人記錄、找不到要明說」【實作，與文件一致】。

**J5 支援提示 → 準備 → 預覽 → 批准分享**
起點（判斷）：`shouldPrompt = shouldOfferSupport(entries)（≥3 條、跨 ≥2 天、≥2 類困難主題）且 entries.length ≥ snoozeUntilCount 且無 openCase`【實作；程式碼與設定頁均註明非臨床判斷】→ 主頁 Notice「A few notes have continued」→ 分支 A「Not now」：`dismissPrompt()` 設 `snoozeUntilCount = 當前條數 + 2`（即再多 2 條記錄才再提示）【實作】→ 回到日常錄音。分支 B「See options」→【實作】`/prompt` 顯示 `supportPromptCopy`（依主題組合的固定模板句）＋「Unfold does not diagnose, score, or contact anyone by itself.」→「Prepare summary」→【實作】`/prepare` 觸發 `prepareDraft()`：`buildDraft` 產生兩句結論（mainConcerns/recentChange，關鍵字規則）、期間標籤、最後 6 條的去標識首句摘錄、已移除 token 清單 →【實作】`/review`：兩句結論**可編輯**、`TokenRow` 隱私檢查、可展開「See what will be shared」查看去標識摘錄 → 判斷：「Approve sharing」→【實作】`approveSharing()` 建立 `CaseItem{status:'queued'}` 並清空 draft → 終點 `/shared`「Only the summary was shared.」。例外：review 頁「Not now」→ 回主頁，draft 保留在 store【實作；之後是否自動重備：未知】。
對照：文件主張「學生不需閱讀完整專業報告、簡單選擇即可」——實作折衷為兩句可編輯結論＋可展開摘錄（中期報告中文版已自述此折衷）【實作，與最新文件一致】；「GenAI 背景分析與閾值」【文件主張未實作，現為關鍵字規則】。

**J6 分享後：等待 → 回覆 → 繼續／換人／撤回**
起點：個案 `queued` →【實作】學生端 `/case` 顯示「Waiting for a reply」，可「Withdraw sharing」→ 社工回覆（見 J8）使狀態變 `replied`、`seenReply=false` →【實作】主頁出現 Notice「A social worker replied」→ 行動：讀回覆（`/case` 自動 `markReplySeen`）→ 判斷三分支：①「Continue the conversation」→ `continued`，可與社工互傳訊息（單條 ≤500 字）【實作】；②「Ask for someone else」→ `rematch`，摘要回隊列【實作】；③「Withdraw sharing」→ `withdrawn` 且 `snoozeUntilCount = 條數 + 2`【實作】→ 終點。
例外：rematch 後無第二個社工接案的處理【實作上同一隊列可再回覆；真實「無人接案」流程：文件主張未定、實作無超時機制】→ 無法測試；撤回後「已被讀資訊如何處理」——實作僅從雙方介面隱藏，資料仍存 AsyncStorage【實作可觀察；保留語義：文件自認未定義】。
對照：文件「接受聯絡／要求重新匹配／撤回分享」【實作，三分支皆在】；「提交後新記錄是否併入個案」【文件自認未定；實作：新記錄不影響已建個案】。

**J7 設定與資料刪除**
起點：`/settings`（由 diary 或 privacy 進入）→ 行動：「Load a sample week」載入 4 條合成示例並重設 snooze【實作】；「Delete everything」→ 兩步確認 → `clearAll()` 清空全部 entries/cases/messages/draft，保留 `onboarded=true`【實作】→ 終點回主頁。設定頁明示提示規則為簡單模式檢查、非臨床判斷【實作】。

### 社工端（同機模擬）

**J8 隊列 → 讀摘要 → 回覆**
起點：`/shared` 頁「Open social worker view」或直接進 `/worker`【實作；**無任何身份驗證或權限檢查，同機任何人可開啟**】→【實作】`/worker` 列出所有非 withdrawn 個案（狀態、兩句結論、日期）→ 行動：點個案 →【實作】`/worker/[id]` 顯示：去標識兩句結論、期間、去標識摘錄、「Removed before sharing」token 清單、訊息串；明示音頻不在隊列 → 行動：撰寫回覆「Send reply」→【實作】`sendMessage(caseId,'worker',…)`：若狀態 queued/rematch → 轉 `replied` 且學生端 `seenReply=false` → 終點：學生端 J6 接手。
例外：個案被撤回後，worker 個案頁顯示「This summary is no longer shared.」且從隊列消失【實作】。
可見／不可見：社工可見＝去標識結論＋摘錄＋訊息【實作】；不可見＝原始全文稿、音頻【實作：摘要只含 `excerpts`（去標識首句），全文稿不進 CaseItem；程式碼層面成立，但同機 AsyncStorage 內全文稿物理上仍在】。
對照：文件「社工按專長、語言、工作量選案、身份驗證」【文件主張，全部未實作 → 無法測試】。

產品實際只有一條跨角色交接：**學生 → 社工的摘要提交與回覆**（同機模擬）。其餘文件主張的交接（機構派案、換人後的另一社工、撤回後的資料處理）未實作。

| 項目 | 內容 | 狀態 |
| --- | --- | --- |
| 發起方 | 學生，在 `/review` 按「Approve sharing」 | 【實作】 |

## 4. 使用者 agent 任務卡（N = 3）

角色依產品實際參與者決定：**UA-S 中學生、UA-U 大學生、UA-W 社工**。注意：實作對 UA-S 與 UA-U **完全無區分**（無年齡、監護人、權限差異），UA-S 卡的多數保護相關判準將是「無法測試／缺口記錄」，這本身是評估發現。

### UA-S｜中學生（合成）
- **角色 ID**：UA-S
- **情境**：首次使用的中學生，關注隱私理解、引導勾選、錄音不可用時的回退、以及「未成年人保護流程是否存在」的缺口盤點。
- **測試身份與權限**：合成學生帳戶（實為無帳戶，全新安裝狀態）；僅學生端操作權。
- **起始狀態**：全新安裝（`onboarded=false`，無 entries）。
- **目標**：完成 J1→J2（含 mic 失敗回退）→J3；盤點保護缺口。
- **步驟**：① 逐步閱讀 onboarding 三頁並記錄理解；② 不勾選時確認 Start 不可用，勾選後完成；③ 模擬麥克風拒絕 → 確認落入打字回退；④ 打字儲存一條合成記錄；⑤ 在 saved 頁選擇事發時間；⑥ 到 diary/day 查看摘要與「非評估」聲明；⑦ 閱讀 privacy 頁並回述「哪些上雲、哪些留機」。
- **禁止操作**：不輸入任何真實個資或真實經歷；不開啟 `/worker`（除非任務明確要求驗證權限缺口，屆時只記錄、不操作個案）；不修改程式碼或設定檔。
- **合成輸入**：固定合成句，如「Today I had a group project meeting and felt the allocation was unfair.」（英文）與一句粵語語意的中文合成句（用於去標識化缺口觀察，如含虛構中文姓名「陳小明」）。
- **成功判準**：引導可完成且勾選閘門生效；mic 失敗回退可用；記錄出現在 diary；學生能正確回述資料流向。**預期缺口（記錄而非失敗）**：無監護人同意、無年齡區分、無緊急支援引導（privacy 頁有一句「不提供緊急協助」文案【實作】）；中文姓名未被去標識化。
- **失敗判準**：未勾選仍可完成引導；回退路徑死結；記錄儲存後消失。
- **期望證據**：每步畫面截圖或狀態轉儲＋事件紀錄（依 api_reference §3 欄位）。
- **依賴**：無（可與 UA-U 並行，但須各自隔離環境或先後重置）。

### UA-U｜大學生（合成）
- **角色 ID**：UA-U
- **情境**：主要全流程角色：自由記錄一週 → 觸發支援提示 → 準備／編輯／批准摘要 → 收到社工回覆後走完三個分支。
- **測試身份與權限**：合成大學生；學生端全部功能。
- **起始狀態**：已完成 onboarding，無記錄（或先載入 sample week 作對照後清除）。
- **目標**：走完 J2×多條 → J3 → J4 → J5（含 Not now snooze 驗證）→ J6 三分支（continue→訊息、rematch→回隊列、withdraw→雙端隱藏）。

### UA-W｜社工（合成，同機模擬）
- **角色 ID**：UA-W

- **起始狀態**：UA-U（或 UA-S 不適用）已完成至少一次 Approve，隊列有 ≥1 個 queued 個案。

- **禁止操作**：不開啟學生端頁面（除驗證需要且經任務卡允許的狀態核對）；不記錄任何真實社工做法結論。

- **失敗判準**：能看到未去標識的合成識別資訊或音頻；撤回後仍可取閱。
- **期望證據**：同 UA-U，另附與學生端事件共享的 `handoff_id` 事件序列（發送→授權→接收→撤回）。
- **依賴**：必須等 UA-U 完成產品內 Approve 後啟動。

## 6. 計劃與空白

- 提示規則：邊界案例（2 條 vs 3 條、單日 vs 跨日、1 類 vs 2 類困難主題）。

**未覆蓋／無法覆蓋的路徑與風險**
